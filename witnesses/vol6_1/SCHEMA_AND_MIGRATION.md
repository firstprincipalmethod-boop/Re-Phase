## Envelope

Each spec has exact top-level keys: `id`, `source_volume`, `source_section`,
`kind`, `role`, `status`, `count_objects`, `spec`, `schema_version`, `suite_version`,
`source`. `count_objects` describes the counting scope and stores no expected
numeric output. Schema version is the integer 2, not Boolean or float.
The source object pins DOI, 10/21 edition, layout and PDF SHA-256 and names the
source relationship. The executable definition is `contract.py`.

Each computed result has `id`, `schema_version`, `suite_version`, `source_volume`,
`kind`, `role_label`, canonical-spec `spec_sha256`, and `computed`.
A golden snapshot is this complete envelope. A generated output wraps it under
`result` and adds `verification` for the local fixed-suite gate. The verification
wrapper is not part of the mathematical computed result; it is generated by the
runner after comparison. JSON object-key order is not semantic; list order and
primitive types are checked exactly.

## No false promotion

`null` means not checked where explicitly documented, not false or a missing key.
`target_check: vacuous_empty_lift` is paired with `recoverable: false`, so an empty
fiber is not recoverable. `cpre_claim_status: not_certified` remains unchanged.
A new file hash, source DOI, candidate label or golden agreement is not a new
external certification.
